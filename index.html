02 / 先理解机制

中转站是什么？

你买到的是上游模型的调用额度，以及一条转发请求的服务链路。

模型客户端通常允许修改请求地址，也就是 Base URL。把官方地址换成第三方网关后，请求会先到中转站，由它用自己的上游凭证调用模型，再把响应返回给你。网关还可以提供统一密钥、限流、模型路由和计费。

你的客户端应用 / SDK / 编程工具→中转网关鉴权 / 路由 / 计费→上游模型API / 云渠道 / 账号池

选择中转站API，重点了解两件事：上游额度来源，以及网关的请求处理方式。上游渠道决定模型与计费，网关负责协议兼容、缓存、工具调用和数据管理。

一个 Key 接入多个厂商，配合统一充值和用量管理，可以减少账号配置与接口适配。日常对话、编程工具和自己的应用，都可以按所需模型选择对应线路。

03 / 上游来源

三种服务类型，先问清买的是哪一种。

按模型、分组和上游渠道比较，就能看清服务能力与计费方式。

A

API转售：转发官方或云渠道额度

上游使用官方 API、企业额度或云厂商渠道，通常按 token 计费。选择时对比模型版本、缓存、上下文和工具调用，再根据客户端选择原生或兼容接口。

要问：具体上游、输入输出单价、缓存账单、故障时是否切换渠道。

B

订阅池与逆向适配：把产品额度转换成接口

将订阅账号或产品内的调用额度包装为 API，按对应产品的额度与计费方式提供服务。适合按预算体验模型与编程工具，选分组时重点查看请求次数、并发、额度周期和接口能力。

Kiro逆向是什么？

通常指适配 Kiro 客户端的调用链路，向外提供模型接口。接入时查看对应模型、额度周期和客户端支持，编程场景重点体验缓存、工具调用、上下文与响应速度。

要问：每次或每天额度、支持的客户端、模型映射与客服响应。

C

聚合网关：统一接入多个供应商

在一套接口内选择多家模型服务，提供统一账单和路由，方便项目同时使用多个模型。通过供应商目录、数据政策和实际单价选择线路；OpenRouter 等服务也能用于比价。

要问：模型由谁提供、自动路由到哪里、费用是否包含额外手续费。

04 / 费用怎么算

倍率好看，账单也要算得清。

比较API中转站的价格，把人民币实付、站内额度和真实请求消耗放在同一张账上。

1. 先分清三种“倍率”

官方价折扣指相对于官方单价的比例；模型倍率是面板相对某个计费基准的系数；分组倍率是你所在分组叠加的系数。看到“0.3倍”时，先对应到它的计费口径，再换算实际单价。

常见 new-api 的 token 计费口径使用 500,000 额度单位对应 1 个系统美元；输入模型倍率为 1 时，对应每百万输入 token 2 个系统美元。按token、固定价格和按次计费使用各自的计算方式，下面先算输入与输出token的费用。

按token计费示例 · 输入与输出费用

消耗额度 = 分组倍率 × 模型倍率
×（输入token + 输出token × 补全倍率）÷ 500,000

2. 充值换算和余额显示是两回事

把站内额度按充值比例换算成人民币，就能看清实际调用成本。记录实际付了多少人民币、到账多少额度、使用哪个分组。显示为 ¥、$ 或积分，只是余额的展示方式。

一笔账算完 · 以下均为假设数字

付70元，到账10个系统美元额度

假设分组倍率0.5、模型倍率1、补全倍率5；一次请求输入100,000 token、输出10,000 token，不涉及缓存。

请求消耗
0.5 × 1 × (100,000 + 10,000 × 5) ÷ 500,000 = 0.15额度
额度成本
70元 ÷ 10额度 = 7元 / 额度
人民币成本
0.15额度 × 7元 = 1.05元

比较每家时都算到人民币实付这一步，用同一任务的最终费用判断性价比。

3. 用缓存优化长任务成本

编程工具常在后续请求里重复发送上下文。支持缓存的线路会按分组价格分别计算常规输入、缓存命中与缓存写入。查看请求明细里的缓存读写用量，更容易找到适合长会话的计费方案。

举个假设：一段输入按常规价每百万2元、缓存命中价0.2元计费。另一条线路即使常规价降到1元，若所有输入都按常规价扣，同样的缓存命中内容也会贵5倍。对长会话，把缓存费用一起算进去，比较价格更准确。

4. 按量、按次与套餐，分别算

  • 按量：按输入、输出与缓存等用量扣费，适合查每次请求明细。
  • 按次：一次调用固定扣费，按任务的请求次数比较成本，同时查看重试和工具调用的计次规则。
  • 套餐：日卡、月卡或订阅常有额度、模型、并发和有效期限制。用实际能完成的任务数比较。

5. 用三步核对真实费用

  1. 先看后台是否列出输入、输出、缓存读写、使用分组和扣费。
  2. 在两家用相同任务和上下文测试，保存请求用量及最终扣费；模型输出长度不同也要算进去。
  3. 首充后检查赠额和充值余额的扣款顺序、有效期，以及失败重试是否收费。

计费机制参考 new-api 项目 ↗。用所选分组的价格和请求账单，计算自己的调用成本。

05 / 选择方法

API中转站怎么选？

从模型、接口、预算和服务四个方面选择，接入后用真实任务体验效果。

  1. 确定模型与客户端

    写下完整模型 ID、所需协议、上下文、工具调用和并发。GPT API中转站是否支持客户端所需的接口，Claude 线路是否透传缓存，比“支持几十种模型”更值得先问。

  2. 核对站点与条款

    查看运营主体、公告、服务条款、退款规则和近期社区反馈。把客服响应、公告更新和服务政策一起比较，长期使用更好管理。

  3. 算实际成本

    拿你会用的模型和分组算输入、输出、缓存与充值换算。做API平台推荐比较时，用任务最终扣费和任务完成情况作为尺度。

  4. 用真实任务体验

    把常见任务、长上下文、结构化输出、工具调用与流式输出都跑一遍。白天和晚高峰各测试，记录首字时间、完整响应、失败与重试。

  5. 配好用量与备用线路

    按近期需求充值，给 Key 设置额度上限。保留一条测试过的备用线路，定期检查模型映射、分组和账单是否变化。

06 / 使用与避坑

接得上，还要用得明白。

配好模型、计费与密钥，日常使用和项目接入更顺手。

模型选择：按任务体验能力

使用固定的一组任务，比较上下文、结构化输出、工具调用与图片输入。把模型 ID、输出质量、响应时间和扣费记录下来，后续调整模型与分组时可以直接对比。

用量管理：按任务预算充值

根据模型单价和近期任务量安排充值，把赠额、充值余额与套餐有效期分开记录。查看退款条件和用量明细，给项目设置额度上限，方便管理长期成本。

数据管理：项目独立密钥，日志按需设置

为每个项目配置独立 Key，按业务需求选择日志保留和数据处理方式。团队接入时一并查看隐私设置、删除机制与服务条款，让用量与访问权限便于管理。

接入：按客户端逐项核对

  • Base URL：确认地址是否包含 /v1，原生接口与兼容接口是否使用同一入口。
  • API Key：为每个项目单独建 Key，设限额，避免提交到仓库或放进公开排错日志。
  • 模型 ID：按站点目录填写，确认别名实际映射到哪个版本。
  • 客户端配置：检查旧地址、代理设置和鉴权变量是否冲突，再跑一次最小请求与一次真实任务。
  • 备用线路：提前验证切换方法，服务异常时先看公告和用量，避免盲目重试造成重复扣费。

08 / FAQ

选站和使用时，常问的十件事。

AI中转站推荐最终要落到你需要的模型、真实任务和账单上。

API站、API中转平台和AI中转有什么区别？

API站是提供模型、搜索、语音等接口的网站。AI中转负责转发模型请求；API中转平台在此基础上提供多模型路由、统一计费和用量管理。选站时按模型、协议、计费和服务条件比较，就能找到适合项目的接入方式。

国内API中转站推荐，重点看什么？

重点看国内网络接入、人民币支付、中文文档和客服响应。日常使用时，在自己的网络和常用时段体验响应速度；有国内部署要求的项目，再按实际处理位置、运营主体和合同条款筛选。

中转站API推荐重点看哪些指标？

在线率看服务可用性，首字延迟看响应速度，完整耗时看任务效率。编程和多轮对话还要看工具调用、长上下文与缓存。把这些指标与所需模型一起比较，选站更直接。

API中转平台推荐要看哪些服务条款？

查看余额有效期、退款条件、充值到账单位、速率与并发、日志设置和联系渠道。需要发票或对公付款时，选择提供对应服务的站点；清楚的账单和服务条款便于长期管理用量。

GPT API中转站和GPT6中转站怎样接入？

在站点模型目录找到完整模型 ID，配置 Base URL 与 API Key，再选择客户端使用的 Responses 或 Chat Completions 接口。编程场景重点体验流式输出、工具调用、上下文与缓存；多模态任务再查看图片等输入能力。

Gemini中转站、GLM中转站怎样搭配？

按任务选择模型。Gemini 常用于多模态与长文档，GLM 可用于中文应用和工具调用。统一接口便于在项目里切换模型，再用同一组任务比较输出质量、响应速度和实际扣费。

低倍率和注册赠额怎样比较？

把官方价折扣、面板模型倍率和分组倍率分开计算，再加上充值换算、输出与缓存费用。注册赠额适合体验线路，使用前查看额度单位、有效期、支持模型以及扣款顺序。按任务的最终人民币成本比较最清楚。

API推荐和API ranking榜单怎样搭配使用？

先从站点清单选出需要的模型，再在禾维 AI 查看具体模型的近期实测，在 AI API Rank 比较综合排名、在线率、延迟、支付与服务政策。把模型表现和服务条件放在一起，能更快缩小选择范围。

中转站怎样处理请求数据？

中转网关接收请求、调用上游模型并返回响应。HTTPS 保护传输过程，日志保留与数据用途在站点隐私设置或服务条款中查看。团队项目可按数据处理、签约和审计要求选择服务，为每个项目配置独立密钥。

突然出现401、404、429，怎么排查？

401 先检查 API Key、鉴权格式及客户端变量；404 检查 Base URL、是否需要 /v1 和模型 ID；429 查看余额、速率、并发限制及上游公告。网页可访问而请求失败时，分别检查 API 连通性和客户端配置。不要把含完整 Key 的日志发到公开群。
